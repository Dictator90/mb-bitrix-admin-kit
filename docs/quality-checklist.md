# Documentation quality checklist

Перед merge изменений в документации проверьте:

- Не документируется несуществующий/внутренний API как публичный.
- Все PHP-примеры оформлены fenced-блоками с языком `php`.
- Все относительные ссылки рабочие и указывают на существующие файлы.
- Таблицы оформлены как корректные markdown-таблицы.
- Каждый пользовательский раздел содержит: «Что это», «Когда использовать», «Базовый пример», «Методы/сценарии», «Связанные разделы».
- Сохранен Bitrix-native подход: `bitrix:main.ui.grid`, `main.ui.filter`, SidePanel, UI extensions.
- User docs и Dev docs разделены; внутренние детали не перегружают quick-start.
- После правок выполнен markdown/link audit.
- Если менялись примеры/политики: запущены `composer cs-fix` и `composer test`.
